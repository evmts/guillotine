# Project status

Guillotine is **early alpha**. The repository's own words: *do not use in
production*. Any use should be considered purely experimental.

This page records measured results. Each number names its source. The runs
below were made on `maint/unified-v8` (`d4c0725d`, 2026-11-25, Linux x86_64,
Zig 0.17.1) and are recorded in that lineage's integration report.

## Ethereum spec compliance

### EEST state tests: 66,652 / 66,652 (100.00%)

`zig build state-tests` runs the official pre-filled Ethereum Execution Spec
Tests against the `src/` engine. Fixtures are `tests@v21.0.3`, pinned by release
tag and SHA-256 in `scripts/fetch-eest-fixtures.sh`.

| Run | Cases | Passed | Failed |
| --- | ---: | ---: | ---: |
| Fusion on (default) | 66,652 | 66,652 | 0 |
| Fusion off (`-Devm-enable-fusion=false`) | 66,652 | 66,652 | 0 |

- Forks: Frontier through Osaka, every fork at 100.00%.
- 16,907 Amsterdam cases are skipped because Guillotine does not support that
  fork yet.
- Crashes: 0.

### Lean 4 differential fuzzing: 116,384 / 116,384

`zig build test-lean-diff` generates inputs, runs them through Guillotine and
through a Lean 4 reference model (`verify/lean`), and compares the results. The
recorded run (default seed, 2,000 iterations per campaign) matched on all
116,384 cases, with zero mismatches and zero crashes, across word operations,
gas and refunds, bytecode analysis, EVM execution, Base/OP Stack rules, and RLP.

### Legacy filler specs

`zig build specs` runs the older filler-based suite under `specs/cases/`. It
does not pass yet and is not a CI gate. The official state tests above
supersede it.

:::danger
Guillotine is still alpha. Passing every official state test means the engine
agrees with Ethereum on those inputs. It does not cover block processing,
networking, or inputs the fixtures and fuzzers never generate, and the code has
had no external audit. Do not use it to compute anything you rely on (balances,
gas estimates, state roots) without cross-checking against a mature
implementation.
:::

## Checks

### CI

`.github/workflows/ci.yml` runs on every push and pull request:

| Job | What it runs |
| --- | --- |
| `ast-check` | `zig ast-check` on every tracked `*.zig` file |
| `build-test` (macOS arm64, Ubuntu x86_64) | `cargo test --locked`, `zig build`, `test-unit`, `test-opcodes`, `test-modexp`, `test-precompiles`, `test-layer2`, `test-bench`, `test-fusions`, `shared static -Doptimize=ReleaseFast`, the C SDK tests and the TypeScript SDK tests |
| `state-tests` (fusion on, fusion off) | `zig build state-tests -Doptimize=ReleaseSafe`, then asserts 66,652 of 66,652 cases passed |

`.github/workflows/fuzz.yml` runs the Zig fuzz targets, a multi-threaded fuzz
campaign, the Rust BN254/BLS12-381 FFI fuzz tests, and the TypeScript SDK fuzz
suite, nightly and on pull requests. `.github/workflows/release.yml` builds and
publishes a release when a `v*` tag is pushed. See
[Language bindings](/guides/bindings#npm-packaging).

## Feature support

| Area | State |
| --- | --- |
| Ethereum mainnet | The only network `Evm` executes |
| OP Stack (Optimism, Base) | `src/layer2/` implements fee, deposit and precompile rules and a transaction executor for an execution host (`src/layer2/executor.zig`, `zig build test-layer2`). `EvmConfig` has no Layer 2 field. |
| Arbitrum Nitro | Not implemented. Planned for beta. |
| Hardforks | `Hardfork` spans `FRONTIER` through `AMSTERDAM`; the default is `OSAKA`. `state-tests` covers Frontier through Osaka. |
| Precompiles | `0x01`–`0x11` and `P256VERIFY` (`0x100`, Osaka) in `lib/voltaire/src/precompiles/` |
| C ABI | Experimental (`sdks/c/`, `src/evm_c_api.zig`) |
| TypeScript (`@tevm/guillotine`) | Experimental; Bun only, over the native library. Prebuilds for `darwin-arm64` and `linux-x64`. |
| WASM | No root build step for the `src/` engine. guillotine-mini builds with `cd mini && zig build wasm`. |
