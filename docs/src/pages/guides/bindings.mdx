# Language bindings

The cross-language surface is a C ABI: `src/evm_c_api.zig` exports a flat,
opaque-handle C interface, declared in `sdks/c/include/guillotine.h`.
`sdks/README.md` lists what the repository ships:

| Surface | Directory | Status | Mechanism |
| --- | --- | --- | --- |
| Zig | `src/root.zig` | Beta | Zig package; import `dep.module("evm")` (`voltaire`, `crypto`, `precompiles`, `layer2`) |
| EVMC v12 | `src/evmc_c_api.zig`, `sdks/c/include/evmc_guillotine.h` | Beta | Standard EVMC ABI v12 (`evmc_create_guillotine`) |
| C | `sdks/c/` | Beta | C ABI v2 directly (`guillotine.h`, `GuillotineHostVTable`, `execute_tx`) |
| TypeScript, `@tevm/guillotine` | `sdks/typescript/` | Beta; Node.js ≥ 20 & Bun ≥ 1.1; 341 / 341 tests pass on both backends | Zero-`node-gyp` Node-API (`guillotine.node`) and Bun FFI (`libguillotine_ffi`) |

Python, Go, Rust, Swift, Kotlin/JNI, and native Bun integrations are custom
SDKs you build on the C ABI; the repository does not maintain them. Start with
[Building custom SDKs](https://github.com/evmts/guillotine/blob/main/docs/building-custom-sdks.md)
and the Custom SDK Builder skill
(`.agents/skills/guillotine-sdk-builder/SKILL.md`).

## The C ABI

Build a linkable library first:

```bash
zig build shared    # dynamic library for FFI (`libguillotine_ffi`)
zig build napi      # zero-node-gyp Node-API addon (`guillotine.node`)
zig build evmc      # EVMC ABI v12 shared library (`libguillotine_evmc`)
zig build static    # static library; links only with extra archives, see below
```

Both install to `zig-out/lib/`: `libguillotine_ffi.dylib` on macOS or
`libguillotine_ffi.so` on Linux, and `libguillotine_ffi_static.a`. Releases
ship only the shared library: the static archive does not bundle `libblst`,
`libcrypto_wrappers` or `libckzg`, so a consumer cannot link it alone. Prebuilt
`libguillotine_ffi.so` (x86_64, glibc >= 2.28), `libguillotine_ffi.dylib`
(arm64) and `guillotine.h` are attached to each
[GitHub Release](https://github.com/evmts/guillotine/releases) with
`SHA256SUMS.txt`. The C SDK
checks the header and runs native tests with `make -f sdks/c/Makefile simple`
and `make -f sdks/c/Makefile test`.

The surface is an opaque-handle lifecycle. Names verified from
`src/evm_c_api.zig`:

### Lifecycle

```c
void  guillotine_init(void);
void  guillotine_cleanup(void);

EvmHandle* guillotine_evm_create(const BlockInfoFFI* block_info);
EvmHandle* guillotine_evm_create_mainnet(const BlockInfoFFI* block_info);
EvmHandle* guillotine_evm_create_with_config(const BlockInfoFFI* block_info,
                                             EvmConfiguration config);
EvmHandle* guillotine_evm_create_tracing(const BlockInfoFFI* block_info);
EvmHandle* guillotine_evm_create_call_tracer(const BlockInfoFFI* block_info);
EvmHandle* guillotine_evm_create_test(const BlockInfoFFI* block_info);
EvmHandle* guillotine_evm_create_with_fork(const BlockInfoFFI* block_info, uint8_t hardfork_id);
EvmHandle* guillotine_evm_create_with_host(const BlockInfoFFI* block_info,
                                           const GuillotineHostVTable* vtable,
                                           void* user_ctx);
bool       guillotine_set_block_info(EvmHandle* handle, const BlockInfoFFI* block_info);

void guillotine_evm_destroy(EvmHandle* handle);
void guillotine_evm_destroy_tracing(EvmHandle* handle);
```

Every handle is an opaque monotonic registry token stored in a tagged `HandleBox`, so **all state, simulation, execution, and dump functions work on every handle configuration** (mainnet, `structLogs` tracer, `callTracer`, test mode, fork-selected, and external host callback). The `*_tracing` entry points remain as backwards-compatible aliases.

### State

```c
bool guillotine_set_balance(EvmHandle*, const uint8_t address[20], const uint8_t balance[32]);
bool guillotine_set_nonce  (EvmHandle*, const uint8_t address[20], uint64_t nonce);
bool guillotine_set_code   (EvmHandle*, const uint8_t address[20], const uint8_t* code, size_t code_len);
bool guillotine_set_storage(EvmHandle*, const uint8_t address[20], const uint8_t key[32], const uint8_t value[32]);

bool guillotine_get_balance(EvmHandle*, const uint8_t address[20], uint8_t balance_out[32]);
bool guillotine_get_nonce  (EvmHandle*, const uint8_t address[20], uint64_t* nonce_out);
bool guillotine_get_storage(EvmHandle*, const uint8_t address[20], const uint8_t key[32], uint8_t value_out[32]);
bool guillotine_get_code   (EvmHandle*, const uint8_t address[20], uint8_t** code_out, size_t* len_out);
```

`u256` crosses the boundary as a 32-byte big-endian array. Addresses are 20 raw
bytes. There are no bignum structs in the ABI.

### Execution

```c
EvmResult* guillotine_call        (EvmHandle*, const CallParams* params);
EvmResult* guillotine_call_tracing(EvmHandle*, const CallParams* params);
EvmResult* guillotine_simulate    (EvmHandle*, const CallParams* params);
EvmResult* guillotine_execute_tx  (EvmHandle*, const TxParamsFFI* params);
```

### Freeing

Zig allocated it, so Zig must free it. Never call `free()` on anything the ABI
returned:

```c
void guillotine_free_result(EvmResult* result);
void guillotine_free_output(uint8_t* output, size_t len);
void guillotine_free_code  (uint8_t* code,   size_t len);
```

### Errors

```c
const char* guillotine_get_last_error(void);
```

Functions returning `bool` report failure as `false`; call
`guillotine_get_last_error()` for the message. Functions returning a pointer
report failure as `NULL`.

### Bytecode analysis without execution

```c
BytecodeHandle* evm_bytecode_create(const uint8_t* data, size_t data_len);
void            evm_bytecode_destroy(BytecodeHandle* handle);
size_t          evm_bytecode_get_length(const BytecodeHandle* handle);
size_t          evm_bytecode_get_runtime_data(const BytecodeHandle* handle, uint8_t* buffer, size_t buffer_len);
uint8_t         evm_bytecode_get_opcode_at(const BytecodeHandle* handle, size_t position);
```

## WASM

The root build has no WASM step for the `src/` engine, and the TypeScript SDK
has no WASM backend (`sdks/typescript/README.md`).

The separate [`evmts/guillotine-mini`](https://github.com/evmts/guillotine-mini)
repository builds its own WASM module with its own C exports.

## npm packaging

The TypeScript SDK is `@tevm/guillotine` (`sdks/typescript/package.json`). It
runs natively in **Node.js ≥ 20** (via the zero-`node-gyp` Node-API addon
`guillotine.node`) and **Bun ≥ 1.1** (via either `guillotine.node` or Bun FFI
over `libguillotine_ffi`). `bun run build:native` builds both artifacts in
ReleaseFast with `-Dstrip=true` and copies them into `prebuilds/<platform>-<arch>/`.
For custom paths, set `GUILLOTINE_NAPI_PATH` (for `guillotine.node`) or
`GUILLOTINE_LIB_PATH` (for `libguillotine_ffi`). See [Embedding Guillotine](/guides/embedding)
and [Publishing and releases](/guides/publishing).

## Which should I use?

- **Zig**: add the package and import `guillotine.module("evm")`. See
  [Installation](/installation#use-it-from-a-zig-project).
- **C, or a language with a C FFI**: link `libguillotine_ffi` and include
  `sdks/c/include/guillotine.h`.
- **TypeScript on Bun**: `@tevm/guillotine`.
- **A browser**: the WASM build of the separate
  [`evmts/guillotine-mini`](https://github.com/evmts/guillotine-mini) repository.
  The `src/` engine has none.
