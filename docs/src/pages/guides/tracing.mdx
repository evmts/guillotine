# Tracing and debugging

Guillotine ships a tracer that does something unusual: it runs a second,
independent EVM alongside the fast one and asserts after every instruction that
they agree. That machine is `MinimalEvm`, a plain switch-loop interpreter in
`src/tracer/minimal_evm.zig` (with `minimal_frame.zig` and `minimal_host.zig`).

When the fast path and the reference disagree, you get told exactly which
instruction diverged and how, instead of discovering a wrong state root ten
thousand instructions later.

## Enabling the tracer

The tracer is a comptime config, so a traced EVM is a different type with
different generated code. The per-instruction hooks (`beforeInstruction`,
`afterInstruction`, `afterComplete` in `src/frame/frame.zig`) run in Debug and
ReleaseSafe builds and in any build whose `tracer_config.enabled` is true
(`handler_abi.hooksEnabled`). An untraced ReleaseFast or ReleaseSmall build
compiles them to nothing.

```zig
const Evm = @import("evm").Evm;
const TracerConfig = @import("evm").TracerConfig;

// Nothing at all (the default).
const Fast = Evm(.{ .tracer_config = TracerConfig.disabled });

// Validation + PC + gas tracking + debug logging.
const Debugging = Evm(.{ .tracer_config = TracerConfig.debug });

// Everything, including step capture and advanced trace.
const Everything = Evm(.{ .tracer_config = TracerConfig.full });
```

Or pick individual flags:

```zig
const Stepper = Evm(.{
    .tracer_config = .{
        .enabled = true,
        .enable_step_capture = true,   // record every step for a JSON-RPC trace
        .enable_pc_tracking = true,    // maintain the true bytecode PC
        .enable_gas_tracking = true,   // per-step gas
        .enable_validation = false,    // skip lockstep MinimalEvm comparison
        .enable_debug_logging = false,
        .enable_advanced_trace = false,
    },
});
```

| Flag | Default | What it costs, what it buys |
| --- | --- | --- |
| `enabled` | `false` | Master switch. Everything below is inert without it. |
| `enable_validation` | `false` | Runs `MinimalEvm` in lockstep and compares state. The expensive one, and the one that finds bugs. |
| `enable_step_capture` | `false` | Accumulates a step record per instruction; fills `CallResult.trace`. Allocates. |
| `enable_pc_tracking` | `false` | Tracks the real bytecode PC alongside the cursor. |
| `enable_gas_tracking` | `false` | Per-step gas remaining. |
| `enable_debug_logging` | `false` | Verbose `log.debug` output per instruction. |
| `enable_advanced_trace` | `false` | Extra structured trace detail. |

Two ready-made EVMs already exist in `src/root.zig` if you do not want to
assemble a config:

```zig
const Traced = @import("evm").MainnetEvmWithTracer;  // Osaka + validation, step capture, PC and gas tracking
const Testing = @import("evm").TestEvm;              // Cancun + PC and gas tracking, disable_gas_checks, no validation
```

## Reading a trace

With the tracer enabled, `call` attaches the captured steps to the result as
`trace: ?ExecutionTrace` (`src/frame/call_result.zig`):

```zig
var result = evm.call(params);
defer result.deinit(allocator); // also frees the trace

if (result.trace) |trace| {
    for (trace.steps) |step| {
        std.log.info("pc={d} op={s} gas={d}", .{ step.pc, step.opcode_name, step.gas });
    }
}
```

The raw tracer records are on `evm.tracer.steps.items` (`Tracer.ExecutionStep`
in `src/tracer/tracer.zig`). The C ABI's `guillotine_call_tracing` serialises the
trace as `{"structLogs":[...]}` JSON with `pc`, `op`, `gas`, `gasCost`, `depth`,
`stack`, and `memSize` per step (`writeTraceJson` in `src/evm_c_api.zig`), the
shape `debug_traceTransaction` consumers read.

## How lockstep validation works

Every handler begins with one mandatory line:

```zig
pub fn some_opcode(self: *FrameType, cursor: [*]const Dispatch.Item, sp: [*]WordType, gas: FrameType.GasType) callconv(handler_abi.handler_cc) handler_abi.ExitCode {
    N.before(self, .SOME_OPCODE, cursor, sp, gas); // writes sp and gas back, then calls beforeInstruction
    // ... implementation ...
    return N.next(self, .SOME_OPCODE, cursor, sp, gas);
}
```

`beforeInstruction` advances `MinimalEvm` by the correct number of steps for that
opcode and compares stack, memory, gas, and storage.

For a real opcode that is one step. For a synthetic (fused) opcode it is however
many real opcodes were fused: `PUSH_MSTORE_INLINE` steps the reference twice,
`ISZERO_JUMPI` three times. The mapping lives in `getMaxStepsForOpcode()`,
called by `executeMinimalEvmForOpcode()` in `src/tracer/minimal_evm_sync.zig`.

:::warning[The number one cause of confusing test failures]
A handler that forgets `N.before()` leaves `MinimalEvm` behind. Every
subsequent comparison fails, and the reported divergence points at an innocent
instruction far from the real omission. If a differential test starts failing
after you touched a handler, check that line first.
:::

## Assertions

Use the tracer's `assert()`, never `std.debug.assert()`:

```zig
(&self.getEvm().tracer).assert(self.stack.size() >= 2, "ADD requires 2 stack items");
```

How it behaves:

1. On failure, `Tracer.assert` (`src/tracer/tracer.zig`) logs the message and
   the recent-opcode ring buffer (when the tracer is enabled) and increments
   `Tracer.failed_checks`. Debug and ReleaseSafe builds then panic; ReleaseFast
   and ReleaseSmall builds never abort (`aborts_on_failed_check`).
2. The stack's `_unsafe` operations route their checks through it and skip them
   entirely in ReleaseFast and ReleaseSmall (`src/stack/stack.zig`).
3. Assertions are development aids, not validation. A crash on
   attacker-supplied bytecode is a security bug, so the engine must return an
   error for bad input before any assertion can fire.

## Debugging a divergence

:::steps

### Reproduce it narrowly

```bash
zig build test-opcodes -Dtest-filter='ADD opcode'
zig build test-integration -Dtest-filter='differential'
```

### Turn fusion off

```zig
const Unfused = Evm(.{ .enable_fusion = false, .tracer_config = TracerConfig.debug });
```

If the divergence disappears, it is a fusion or fusion-arity problem, not a
handler problem.

### Print the analysis and the schedule

```zig
const pretty = try bytecode.pretty_print(allocator); // Bytecode(config) analysis
defer allocator.free(pretty);
std.log.info("{s}", .{pretty});
```

For the dispatch schedule itself, use
`@import("evm").dispatch_pretty_print.pretty_print(allocator, schedule, bytecode, FrameType, ItemType)`
or the C export `evm_dispatch_pretty_print`. Schedule indices are not PCs. See
[Dispatch](/concepts/dispatch).

### Compare against the spec fixtures

The `test/differential/` tests compare Guillotine against `MinimalEvm`. When
the two agree with each other but disagree with the world, run the official
fixtures: `zig build state-tests` (see `specs/README.md`).

:::

## Logging

Never `std.debug.print` in a module. Use `src/log.zig`:

```zig
const log = @import("log.zig");

log.debug("cursor={*} gas={d}", .{ cursor, self.gas_remaining });
log.warn("unexpected state: {}", .{state});
```

In tests, raise the level explicitly:

```zig
test {
    std.testing.log_level = .debug;
}
```

A passing Zig test prints nothing regardless of log level. Silence is success.

## The standalone tracer EVM

`MinimalEvm` is small: `src/tracer/minimal_evm.zig` is about 27 KB, plus
`minimal_frame.zig` and `minimal_host.zig`. It has no C API of its own. For a
browser build, use guillotine-mini: `cd mini && zig build wasm`.
