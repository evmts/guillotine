# Installation

Guillotine is a Zig library with vendored C and Rust dependencies. There is no
package to `npm install` for the core engine. Build it from a checkout, or use
one of the [language bindings](/guides/bindings).

## Prerequisites

| Requirement | Version used to verify these docs | Why |
| --- | --- | --- |
| [Zig](https://ziglang.org/download/) | `0.17.1` | The whole engine. `build.zig.zon` declares `minimum_zig_version = "0.17.1"`. |
| [Rust / Cargo](https://rustup.rs) | stable | `lib/voltaire` builds a `crypto_wrappers` staticlib (arkworks BN254/BLS12-381 + keccak) that the Zig build links. |
| A C/C++ toolchain | Apple Clang 17 (Xcode CLT) | `blst`, `c-kzg-4844` and `libc++` linkage. |
| Python 3 | 3.11+ | Only for `zig build test-mini-full` and some spec-fixture tooling. Not needed for a normal build. |

Check what you have:

```bash
zig version
# 0.17.1

cargo --version
# cargo 1.x.y

cc --version
```

:::tip
Zig releases are not backwards compatible at this stage of the language. Pin
`0.17.1`; [zvm](https://github.com/tristanisham/zvm) and
[asdf](https://github.com/asdf-community/asdf-zig) make that painless. `0.16`
and older will not compile this tree.
:::

## Platform support

CI (`.github/workflows/ci.yml`) builds and tests on `macos-latest` (arm64) and
`ubuntu-latest` (x86_64) with Zig 0.17.1, and `.github/workflows/release.yml`
ships prebuilt libraries for those two platforms. The results on
[Project status](/status) were recorded on Linux x86_64.

| Platform | Status |
| --- | --- |
| macOS arm64 | Built and tested in CI; release prebuild |
| macOS x86_64 | The build graph maps it to `x86_64-apple-darwin`; not in CI |
| Linux x86_64 | Built and tested in CI; release prebuild |
| Linux arm64 | The build graph maps it to `aarch64-unknown-linux-gnu`; not in CI |
| Windows | Best-effort, not in CI. `lib/voltaire/lib/build.zig` builds Voltaire's crate for `*-pc-windows-gnu` so Cargo emits `lib*.a`; the root `build.zig` builds the root Cargo workspace for `x86_64-pc-windows-msvc`. |
| `wasm32` | No root `zig build` step builds the engine for WASM. Voltaire's Cargo step builds `wasm32-unknown-unknown` with `--no-default-features --features portable` (pure-Rust keccak) when the target is WASM. guillotine-mini builds its own WASM with `cd mini && zig build wasm`. |

## Clone and build

```bash
git clone https://github.com/evmts/guillotine
cd guillotine
zig build
```

A cold build prints the `blst` compile commands and Cargo progress. Exit status
0 is success; a warm build prints nothing.

The first build is slow. It compiles `blst`, `c-kzg-4844`, the arkworks Rust
crate, and the Foundry compiler wrapper. Expect several minutes. Subsequent
builds hit the Zig and Cargo caches.

### Build options

```bash
# Release modes
zig build --release=fast
zig build --release=small
zig build --release=safe

# Build-configured EVM options
zig build -Devm-hardfork=Cancun -Devm-enable-fusion=false
```

`zig build -h` lists `-Devm-hardfork` (default `OSAKA`), `-Devm-enable-fusion`,
`-Devm-disable-gas`, `-Ddisable-balance-checks`, `-Denable-tracing`,
`-Dmax-call-depth`, `-Dstack-size`, `-Dmemory-limit`, and related flags.
`build.zig` writes them into the `build_options` module, and `getBuildConfig()`
in `src/root.zig` turns them into the `EvmConfig` of `BuildConfiguredEvm` (also
exported as `DefaultEvm`). They do not change an `Evm(.{ ... })` you instantiate
yourself. `-Devm-enable-fusion=false` also switches `zig build state-tests` to
an EVM with fusion off. `-Devm-disable-gas=true` and
`-Ddisable-balance-checks=true` are a compile error outside `-Doptimize=Debug`.
See [Configuring the EVM](/guides/configuration).

## Running the tests

```bash
zig build test              # specs, integration, unit, and lib tests
zig build test-unit         # src/**/*.zig
zig build test-integration  # test/**/*.zig
zig build test-lib          # lib/**/*.zig
zig build test-opcodes      # per-opcode tests (the CI gate)
zig build state-tests       # official EEST state tests (fetch fixtures first)
zig build specs             # legacy filler specs
```

`zig build state-tests` reads fixtures that `scripts/fetch-eest-fixtures.sh`
downloads (`tests@v21.0.3`, checked against a pinned SHA-256). `specs/README.md` documents both spec suites.

Filter with `-Dtest-filter`:

```bash
zig build test-opcodes -Dtest-filter='ADD opcode'
zig build test-integration -Dtest-filter='differential'
```

:::info[Zig tests are silent when they pass]
A passing `zig build test-*` prints nothing but the build summary. No output is
success, not a hung run.
:::

## Known build friction

These are reproduced on a clean checkout.

**macOS SDK 26.4 and later.** Those SDKs list `libSystem` stubs for
`arm64e-macos` but not `arm64-macos`. Zig ignores arm64e stubs, so native links
can fail with `undefined symbol: _abort`. Before building, CI and the release
workflow link a one-line Zig 0.17.1 program against each installed Xcode and set
`DEVELOPER_DIR` to the first whose SDK links (`.github/workflows/ci.yml`,
`.github/workflows/release.yml`). Do the same locally:
`DEVELOPER_DIR=/Applications/Xcode_<version>.app/Contents/Developer zig build`.

**Voltaire's Rust archive is built by `zig build`.** Every step that links the
`voltaire` or `crypto` modules first runs `cargo build --release --locked` in
`lib/voltaire` (its own Cargo workspace, excluded from the root one). Cargo gets
`--target-dir` set to a directory in the Zig cache (`addOutputDirectoryArg` in
`lib/voltaire/build.zig`), and the build links `libcrypto_wrappers.a` from there.
No separate Rust step is needed, `lib/voltaire/target/` is not used, and an
exported `CARGO_TARGET_DIR` does not move the archive. If a build reports
`libcrypto_wrappers.a: file not found`, check that `cargo` is on `PATH` and read
the Cargo error above it.

**Cargo profile warning.** Every build prints:

```
warning: profiles for the non root package will be ignored, specify profiles at the workspace root:
package:   …/lib/foundry-compilers/Cargo.toml
workspace: …/Cargo.toml
```

Harmless. `lib/foundry-compilers` defines a `[profile.release]` that only the
workspace root may set.
