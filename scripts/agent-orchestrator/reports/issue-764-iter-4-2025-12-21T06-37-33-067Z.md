## What I Found
The backward loop fusion optimization requires a fundamentally different approach than existing sequential fusions. It needs:
1. A synthetic opcode with TWO dispatch targets (loop and exit)
2. Branch prediction hints optimized for the "continue loop" case (condition == 0)
3. The dispatch schedule stores two `jump_static` metadata items

2. **Dispatch Schedule Building** - Add handling for the new fusion in `dispatch.zig` `init()` function to emit:

4. **Integration Testing** - Test with the ten-thousand-hashes fixture

The handler and infrastructure are complete. The remaining work is pattern detection and dispatch schedule generation.

## Blockers or Questions
1. **Pattern Detection Complexity**: The backward loop pattern spans multiple basic blocks, making it more complex to detect than sequential fusions. Need to decide:
   - Should we limit the scan distance for loop body size?
   - How to handle nested loops?
   
2. **Tracer Synchronization**: The tracer needs to know how many MinimalEvm steps correspond to this synthetic opcode - this will be the sum of opcodes in the pattern (PUSH+JUMPI at start, loop body, PUSH+JUMP at end).
